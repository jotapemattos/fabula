# 13. Bun, Vitest, tsdown, changesets, Effect pinned

Status: Accepted — 2026-09-08

## Context

Bun is the package manager. Effect 4 is at release-candidate stage and moves frequently.

## Decision

Bun installs and runs scripts; Vitest with `@effect/vitest` runs tests; tsdown builds with
declarations generated by `tsc`; changesets handles releases. `effect` is pinned to
`4.0.0-rc.112` from npm. A checkout of the Effect source at the matching tag is kept
locally at `.vendor/effect` as a read-only reference. It is not a build input and is not
committed — `.gitignore` excludes it.

## Consequences

- `it.layer`, `it.prop` and `TestClock` are available; `bun test` offers no equivalent.
- Declarations go through `tsc` because Effect's inferred types are hostile to isolated
  declarations. Verify the first build does not bundle a copy of `effect`.
- The vendored checkout is the authority on Effect 4 APIs, which move faster than any
  published documentation. Keeping it at the tag matching the installed version is manual:
  check it out again whenever `effect` is bumped, or it silently describes a version the
  code does not compile against.
